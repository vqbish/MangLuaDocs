Патчинг методов ​

Инъекция классов позволяет добавлять в игру совершенно новое поведение. Но что, если вы хотите изменить код, который уже скомпилирован в саму игру? Именно для этого и нужен патчинг. MLua умеет перехватывать (хукать) методы прямо во время выполнения через нативный бэкенд деторов - по смыслу это похоже на популярный Harmony, но встроено прямо в синтаксис языка через удобные атрибуты на обычных функциях Lua.

Каждый обработчик патча принимает ровно один аргумент - frame. Считайте, что frame - это живой контекст вызова функции (context). Он даёт прямой доступ ко всему, что происходит в данном вызове: входящим аргументам, возвращаемому значению, текущей стадии выполнения, а также ячейке (frame.State) для передачи своих данных между стадиями одного и того же перехватчика.

Объявление патча ​

Команда give Mang.Patches открывает доступ к функциям управления патчами. Чтобы пропатчить метод, объявите атрибут прямо над локальной функцией. Атрибут указывает целевой метод игры, количество аргументов (для выбора нужной перегрузки) и дополнительные настройки:

lua
give Mang.Patches

@[Prefix("Assembly-CSharp::PatchExample.TakeDamage", 1, owner = "my-mod")]
local function BlockBigHits(frame)
    if frame.Integer0 > 100 then
        frame.Integer0 = 0
    end
end

Разберём это объявление:

  • Имя атрибута (Prefix, Postfix, Replace, Around, …) - это вид перехвата, определяющий, когда именно сработает ваш хук относительно оригинального метода игры.
  • Строка цели - полное имя метода в формате Сборка::ПространствоИмён.Тип.Метод.
  • Число сразу после цели - количество аргументов метода, помогающее отличить нужную перегрузку.
  • Все параметры после числа - именованные настройки ключ = значение, например owner = "my-mod".

Если имя метода уникально, количество аргументов можно не указывать, а владельца мода можно написать без кавычек:

lua
@[Prefix("Assembly-CSharp::PatchExample.TakeDamage", 1, CoolMod)]
@[Prefix("Assembly-CSharp::PatchExample.Reload", CoolMod)]
@[Prefix(PatchExample.Reload, CoolMod)]
  • Любой позиционный аргумент, который не является числом или опцией с =, читается как имя владельца (owner). Записи CoolMod и owner = "CoolMod" делают одно и то же. Кавычки нужны, только если в имени есть пробелы или запятые.
  • Если у метода нет перегрузок, число аргументов можно опустить.
  • Целевой метод можно писать даже без кавычек через точку (например, PatchExample.Reload), если такое имя однозначно находится среди загруженных сборок.

Функцию-обработчик всегда объявляйте сразу под атрибутом в виде local function.

Виды патчей ​

АтрибутКогда запускается
@[Prefix]Срабатывает до оригинального метода. Идеально подходит для проверки или подмены входящих аргументов.
@[Postfix]Срабатывает сразу после успешного завершения оригинального метода. Позволяет прочитать или изменить результат.
@[Replace]Срабатывает вместо оригинального метода. Тело оригинального метода игры пропускается целиком.
@[Around]Оборачивает оригинальный метод - запускается один раз до него и один раз после него.
@[Finalizer]Срабатывает на этапе выхода из метода даже при возникновении исключений.
@[Patch]Синоним для @[Prefix] (через параметр kind = "Postfix" можно сменить тип).

Если несколько модов патчат один и тот же метод, они объединяются в аккуратную цепочку вызовов: сначала выполняются все префиксы, затем оригинальный метод (если его не заменили), затем все постфиксы и в конце финализаторы.

Что такое Frame (контекст функции) ​

Аргумент frame представляет собой контекст вызова (context) целевого метода. Обращаясь к слотам frame, вы читаете или записываете реальные регистры процессора и ячейки стека, с которыми работает игра:

Слот фреймаЧто означает в контексте вызова
frame.Integer0, frame.Integer1, …Входящие целочисленные аргументы и указатели на объекты (регистры RDX, R8, R9 и др.)
frame.Float0, frame.Float1, …Входящие аргументы с плавающей точкой (регистры XMM)
frame.ReturnIntegerОсновной слот возвращаемого целого числа, флага, enum или указателя на объект
frame.ReturnInteger1Дополнительный целочисленный регистр возврата для составных структур или 128-битных значений
frame.ReturnFloat, frame.ReturnFloat1..3Слоты возврата для дробных чисел и векторных структур (Vector2, Vector3, Vector4, Quaternion)
frame.ReturnVector, frame.ReturnVector1..3Слоты возврата векторных и SIMD значений
frame.IndirectResultУказатель на буфер вызывающей стороны для возврата больших структур
frame.Stage0 - на этапе входа перед оригиналом, 1 - на этапе выхода после него
frame.StateЯчейка для хранения ваших промежуточных данных между стадиями 0 и 1

Как стандартные типы C# отображаются во фрейм:

Тип параметра или возврата в C#Соответствующий слот фрейма
int, uint, long, ulong, byte, bool, char, enumsframe.IntegerN / frame.ReturnInteger
float, doubleframe.FloatN / frame.ReturnFloat
Структуры и векторы (Vector2, Vector3, Vector4, Quaternion)frame.ReturnFloat, frame.ReturnFloat1..3 или frame.IndirectResult
Ссылочные типы: string, object, массивы, классыПередаются как нативный указатель в frame.IntegerN
Методы экземпляра (с this)Поддерживаются: this занимает frame.Integer0, а первый аргумент становится Integer1

frame.State в начале каждого вызова равен 0. Он создан специально для того, чтобы обработчик @[Around] мог легко передать вычисленное значение со стадии "до вызова" на стадию "после вызова".

Префиксы (Prefix) ​

Префикс выполняется до оригинального метода. Изменяя значение в слоте аргумента, вы заставляете оригинальный метод игры увидеть уже ваше новое значение:

lua
@[Prefix("Assembly-CSharp::PatchExample.Heal", 1, owner = "my-mod")]
local function DoubleHealing(frame)
    frame.Integer0 = frame.Integer0 * 2
end

Постфиксы (Postfix) ​

Постфикс выполняется сразу после оригинального метода. Вы можете проверить результат работы метода и скорректировать его:

lua
@[Postfix("Assembly-CSharp::PatchExample.GetScore", 0, owner = "my-mod")]
local function AddBonus(frame)
    frame.ReturnInteger = frame.ReturnInteger + 10
end

Полная замена (Replace) ​

Замена полностью подавляет оригинальный метод игры. Код игры вообще не вызывается, а ваша функция полностью отвечает за формирование результата:

lua
@[Replace("Assembly-CSharp::PatchExample.GetPrice", 0, owner = "my-mod")]
local function AlwaysFree(frame)
    frame.ReturnInteger = 0
end

Оборачивание (Around) и пропуск оригинального метода ​

Хук @[Around] вызывается дважды за один вызов: сначала на стадии frame.Stage == 0 (до оригинального метода), а затем на стадии frame.Stage == 1 (после него). С помощью frame.State можно передавать значения между ними:

lua
@[Around("Assembly-CSharp::PatchExample.TakeDamage", 1, owner = "my-mod")]
local function ClampDamage(frame)
    if frame.Stage == 0 then
        frame.State = frame.Integer0
        if frame.Integer0 > 50 then
            frame.Integer0 = 50
        end
    else
        print("урон был", frame.State, "стал", frame.ReturnInteger)
    end
end

Если на стадии входа (frame.Stage == 0) вернуть из функции число 1, MLua полностью пропустит оригинальный метод:

lua
@[Around("Assembly-CSharp::PatchExample.Buy", 1, owner = "my-mod")]
local function FreePurchases(frame)
    if frame.Stage == 0 then
        frame.ReturnInteger = 1
        return 1
    end
end

Когда на один метод назначено несколько хуков @[Around], они вкладываются друг в друга как матрёшка: вход происходит по порядку, а выход - в строго обратном порядке.

Финализаторы (Finalizer) ​

Финализатор срабатывает на этапе выхода из метода, обеспечивая гарантированную очистку ресурсов:

lua
@[Finalizer("Assembly-CSharp::PatchExample.AddXp", 1, owner = "my-mod")]
local function ObserveCompletion(frame)
    assert(frame.Stage == 1)
    print("результат начисления опыта:", frame.ReturnInteger)
end

Разрешение перегрузок методов ​

Если у метода несколько перегрузок с разным набором типов, укажите типы аргументов в круглых скобках прямо в строке цели. Стандартные псевдонимы C# (int, float, string и т.д.) распознаются автоматически:

lua
@[Prefix("Assembly-CSharp::PatchExample.Select(System.Int32)", owner = "my-mod")]
local function SelectInt(frame)
    frame.Integer0 = frame.Integer0 * 2
end

Параметры атрибутов ​

ОпцияОписание
owner = "..."Идентификатор владельца (мода) - критически важен для безопасного удаления патчей при перезагрузке
priority = nУправляет порядком вызова среди нескольких хуков на один метод
args = n, arity = nЯвное указание количества аргументов вместо позиционного числа
before = "a, b"Гарантирует запуск вашего хука до указанных модов
after = "a, b"Гарантирует запуск вашего хука после указанных модов
kind = "Postfix"Задаёт вид перехвата при использовании общего атрибута @[Patch]

Всегда указывайте owner явно, чтобы ваши патчи можно было корректно обновить или снять при перезагрузке скриптов.

Управление установленными патчами ​

Модуль Mang.Patches даёт полный контроль над активными перехватами:

ФункцияЧто делает
Mang.Patches.installed()Возвращает количество активных в игре патчей
Mang.Patches.unpatchOwner(owner)Удаляет все патчи, зарегистрированные конкретным модом
Mang.Patches.unpatchTarget(target)Снимает все патчи с конкретного метода
Mang.Patches.unpatchAll()Полностью очищает все патчи во всей игре
lua
Mang.Patches.unpatchOwner("my-mod")

Как только с метода снимается последний патч, MLua моментально и чисто восстанавливает оригинальный нативный машинный код игры.

Исследование доступных методов в игре ​

Если вы не знаете точных имён методов игры, модуль Mang.Reflection позволяет быстро просканировать доступные цели:

lua
give Mang.Reflection

local targets = Mang.Reflection.patchTargets()
for i = 1, targets.Count do
    print(targets:Get(i))
end
ФункцияОписание
Mang.Reflection.types()Возвращает имена всех зарегистрированных типов
Mang.Reflection.hasType(name)Проверяет наличие типа в игре
Mang.Reflection.members(name)Список методов и полей экземпляра для типа
Mang.Reflection.staticMembers(name)Список статических методов и полей для типа
Mang.Reflection.patchTargets()Список всех методов, открытых для патчинга
Mang.Reflection.resolvePatch(target, argc)Находит точную каноническую сигнатуру метода

ОшибкаЧто проверить

SignatureMismatchМетод использует неподдерживаемые структуры по значению или слишком сложные типы
