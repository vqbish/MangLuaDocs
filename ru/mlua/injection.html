Инъекция классов в Unity ​

Хотите, чтобы ваш скрипт на MLua работал как полноценный компонент MonoBehaviour в Unity? Именно для этого предназначена инъекция классов. Обычный class - это просто скриптовый объект. А инъецированный класс становится настоящим компонентом Unity, прикрепляется к GameObject и получает стандартные события жизненного цикла движка, такие как Update, Start, Awake и FixedUpdate.

Полный рабочий пример ​

Вот как написать компонент, который плавно вращает объект каждый кадр:

lua
give UnityEngine

@[Component("Spinner")]
class Spinner : MonoBehaviour
    public speed = 90

    public function Update()
        self.transform.Rotate(0, self.speed * Time.deltaTime, 0)
    end
end

-- Создаём куб и прикрепляем наш пользовательский компонент
local cube = GameObject.CreatePrimitive(PrimitiveType.Cube)
local spinner: Spinner = cube:AddComponent<Spinner>()

-- Настраиваем его скорость
spinner.speed = 45

-- Проверяем, что компонент действительно прикреплён
assert(cube:GetComponent<Spinner>() == spinner)

В этом примере:

  • cube - созданный в мире игровой объект (GameObject).
  • spinner - экземпляр вашего скриптового компонента.
  • Внутри методов self указывает на сам компонент.
  • self.gameObject возвращает родительский объект GameObject.
  • self.transform даёт прямой доступ к его Transform.

Атрибут @[Component] ​

Атрибут @[Component("Spinner")] задаёт псевдоним компонента. Он регистрирует класс в системе компонентов MangLua, чтобы Unity мог создавать его и передавать ему события кадров и физики.

Добавление и поиск компонентов ​

Прикрепить компонент к объекту можно двумя способами - через явный дженерик или через вывод типа из локальной переменной:

lua
-- Явный синтаксис дженерика
local spinner: Spinner = cube:AddComponent<Spinner>()

-- Автоматический вывод типа из аннотации переменной
local spinner: Spinner = cube:AddComponent()

-- Поиск уже существующего компонента на объекте
local found: Spinner = cube:GetComponent<Spinner>()
assert(found == spinner)

Метод GetComponent ищет уже существующий компонент на данном GameObject - если компонент ещё не был добавлен, метод вернёт nil.

Наследование и базовые компоненты ​

Вы можете строить удобные иерархии компонентов с помощью обычного наследования и абстрактных классов:

lua
@[Component("BaseMotor")]
abstract class BaseMotor : MonoBehaviour
    public ticks = 0

    public function Update()
        self.ticks = self.ticks + 1
    end
end

@[Component("FastMotor")]
class FastMotor : BaseMotor
    public function Start()
        print("FastMotor успешно запущен!")
    end
end

-- Прикрепляем конкретный класс-наследник
local motor: FastMotor = cube:AddComponent<FastMotor>()

-- Ищем его по типу базового класса
local base: BaseMotor = cube:GetComponent<BaseMotor>()
assert(base == motor)

Обратите внимание: abstract class нельзя прикрепить к объекту напрямую, создавать можно только его конкретные подклассы.

События жизненного цикла Unity ​

Компоненты MLua получают все стандартные вызовы Unity. Метод init является конструктором самого скрипта, но для работы с объектом сцены (gameObject или transform) рекомендуется использовать Awake или Start:

МетодКогда вызывается движком Unity
Awake()Вызывается сразу при создании и прикреплении компонента к объекту сцены
OnEnable()Вызывается при активации компонента или родительского объекта
Start()Вызывается один раз перед самым первым обновлением кадра
Update()Вызывается каждый кадр - идеально для движения, таймеров и чтения ввода
FixedUpdate()Вызывается с фиксированным шагом физики - для расчётов с Rigidbody
LateUpdate()Вызывается в конце каждого кадра после всех Update - отлично подходит для камер
OnDisable()Вызывается при отключении компонента или родительского объекта
OnDestroy()Вызывается непосредственно перед полным уничтожением компонента или объекта

Решение типичных вопросов ​

СитуацияЧто проверить
MonoBehaviour не найденУбедитесь, что в самом верху скрипта написана строка give UnityEngine
Метод Update не вызываетсяПроверьте регистр букв: имена методов Unity чувствительны к регистру (Update, а не update)
Ошибка при добавлении абстрактного классаНельзя добавить abstract class напрямую - добавьте конкретный класс-наследник
GetComponent возвращает nilПроверьте, что компонент был добавлен на этот объект через AddComponent, или что вы ищете его на правильном GameObject
