Patching ​

Class injection lets you add brand new behavior to a Unity game. But what if you want to change code that's already compiled into the game? That's where patching comes in. MLua lets you hook and detour managed methods right at runtime - similar in spirit to Harmony, but built directly into the language with clean attributes on ordinary Lua functions.

Every patch function receives exactly one argument: frame. Think of frame as the function call's execution context (context). It gives you live, direct access to the call: the incoming arguments, the return slot, the current stage of execution, and a scratch slot (frame.State) to pass your own data between before and after stages of the same hook.

Declaring a Patch ​

Loading give Mang.Patches gives you access to patch management functions. To patch a method, attach a patch attribute directly above a local function. The attribute specifies the target method, the argument count (to pick the right overload), and optional settings:

lua
give Mang.Patches

@[Prefix("Assembly-CSharp::PatchExample.TakeDamage", 1, owner = "my-mod")]
local function BlockBigHits(frame)
    if frame.Integer0 > 100 then
        frame.Integer0 = 0
    end
end

Here is how that breaks down:

  • The attribute name (Prefix, Postfix, Replace, Around, …) is the patch kind - it determines when your hook runs relative to the original game method.
  • The target string is the fully qualified method name: Assembly::Namespace.Type.Method.
  • The number right after the target is the argument count, which disambiguates overloads.
  • Any following arguments are name = value options, like owner = "my-mod".

You can also write the owner positionally, or drop the argument count if the method name is unique:

lua
@[Prefix("Assembly-CSharp::PatchExample.TakeDamage", 1, CoolMod)]
@[Prefix("Assembly-CSharp::PatchExample.Reload", CoolMod)]
@[Prefix(PatchExample.Reload, CoolMod)]
  • Any positional argument that isn't a number or key-value option is treated as the owner name. So CoolMod and owner = "CoolMod" do the exact same thing. Quotes are only needed if your owner name has spaces or commas.
  • You can leave out the argument count if there's only one method with that name.
  • You can even write the target unquoted as a dotted path (like PatchExample.Reload) when it resolves unambiguously across loaded assemblies.

Always put the hook function right beneath its attribute as a local function.

Patch Kinds ​

AttributeWhen it runs
@[Prefix]Runs before the original method. Great for reading or modifying incoming arguments.
@[Postfix]Runs after the original method finishes successfully. Perfect for checking or rewriting the return value.
@[Replace]Runs instead of the original method - skips the original game code entirely.
@[Around]Wraps the original method - runs once before it and once after it.
@[Finalizer]Runs on the exit path of the call, even if errors happen.
@[Patch]An alias for @[Prefix] (pass kind = "Postfix" or similar to change it).

If multiple mods patch the same method, they compose cleanly into a chain instead of clobbering each other: all prefixes run first, then the original method (unless skipped or replaced), then all postfixes, and finally any finalizers.

The Frame (Function Context) ​

The frame argument represents the live call context (context) of the target method. When you read or write a slot on frame, you are directly reading or modifying the actual CPU registers and stack slots that the managed method uses:

SlotWhat it represents in the context
frame.Integer0, frame.Integer1, …Incoming integer and pointer arguments (registers RDX, R8, R9, etc.)
frame.Float0, frame.Float1, …Incoming floating-point arguments (XMM / floating registers)
frame.ReturnIntegerPrimary return value for integers, booleans, enums, or object references
frame.ReturnInteger1Secondary integer return register for composite structures or 128-bit values
frame.ReturnFloat, frame.ReturnFloat1..3Return values for floats, doubles, or homogeneous vector structs (Vector2, Vector3, Vector4, Quaternion)
frame.ReturnVector, frame.ReturnVector1..3SIMD / vector return slots
frame.IndirectResultPointer to caller-allocated memory for large struct returns
frame.Stage0 when entering before the original runs, 1 when leaving after it
frame.StateA scratchpad value you can use to pass info from stage 0 to stage 1

Here is how common C# types map onto the frame slots:

Parameter or Return TypeMapped Frame Slot
int, uint, long, ulong, byte, bool, char, enumsframe.IntegerN / frame.ReturnInteger
float, doubleframe.FloatN / frame.ReturnFloat
Structs / vectors (Vector2, Vector3, Vector4, Quaternion)frame.ReturnFloat, frame.ReturnFloat1..3 or frame.IndirectResult
Reference types: string, object, arrays, classesPassed as a native pointer in frame.IntegerN
Instance methods (this)Allowed - this occupies frame.Integer0, and first arg becomes Integer1

frame.State always starts at 0 for a fresh call. It is dedicated to letting a single @[Around] handler pass custom state from its pre-call phase to its post-call phase.

Prefix ​

Prefix runs before the original game method. If you change an argument slot on frame, the game code actually sees your new value:

lua
@[Prefix("Assembly-CSharp::PatchExample.Heal", 1, owner = "my-mod")]
local function DoubleHealing(frame)
    frame.Integer0 = frame.Integer0 * 2
end

Postfix ​

Postfix runs right after the original game method finishes. You can inspect what the game computed and alter the final return value:

lua
@[Postfix("Assembly-CSharp::PatchExample.GetScore", 0, owner = "my-mod")]
local function AddBonus(frame)
    frame.ReturnInteger = frame.ReturnInteger + 10
end

Replace ​

Replace runs instead of the original method. The original game code never runs at all, and your Lua function is entirely responsible for setting the return value:

lua
@[Replace("Assembly-CSharp::PatchExample.GetPrice", 0, owner = "my-mod")]
local function AlwaysFree(frame)
    frame.ReturnInteger = 0
end

Around and Skipping ​

An @[Around] hook is invoked twice during a single call: first at frame.Stage == 0 (before original), and then at frame.Stage == 1 (after original). You can use frame.State to remember values across the two calls:

lua
@[Around("Assembly-CSharp::PatchExample.TakeDamage", 1, owner = "my-mod")]
local function ClampDamage(frame)
    if frame.Stage == 0 then
        frame.State = frame.Integer0
        if frame.Integer0 > 50 then
            frame.Integer0 = 50
        end
    else
        print("damage was", frame.State, "now", frame.ReturnInteger)
    end
end

If you return 1 from the enter stage (frame.Stage == 0), MLua skips the original method completely:

lua
@[Around("Assembly-CSharp::PatchExample.Buy", 1, owner = "my-mod")]
local function FreePurchases(frame)
    if frame.Stage == 0 then
        frame.ReturnInteger = 1
        return 1
    end
end

When multiple @[Around] hooks exist on one method, they nest cleanly like layers of an onion: entering in order, and exiting in reverse order.

Finalizer ​

Finalizers execute on the leave path of the call, ensuring clean cleanup:

lua
@[Finalizer("Assembly-CSharp::PatchExample.AddXp", 1, owner = "my-mod")]
local function ObserveCompletion(frame)
    assert(frame.Stage == 1)
    print("result", frame.ReturnInteger)
end

Overloads and Typed Targets ​

When a method has several overloads, disambiguate them by writing parameter types in parentheses right in the target string. Common C# aliases (int, float, string, etc.) are recognized automatically:

lua
@[Prefix("Assembly-CSharp::PatchExample.Select(System.Int32)", owner = "my-mod")]
local function SelectInt(frame)
    frame.Integer0 = frame.Integer0 * 2
end

If the parameter count alone is unique, you can just pass the integer arity.

Options ​

OptionWhat it does
owner = "..."Identifier for your mod - essential if you want to cleanly remove your patches later
priority = nControls execution order among multiple hooks on the same target
args = n, arity = nAlternative way to specify parameter count
before = "a, b"Ensures your hook runs before the specified owners
after = "a, b"Ensures your hook runs after the specified owners
kind = "Postfix"Changes the hook type when using generic @[Patch]

Always set owner explicitly so you can cleanly uninstall your hooks on mod reload.

Removing Patches ​

The Mang.Patches module lets you remove hooks cleanly at runtime:

FunctionDescription
Mang.Patches.installed()Returns the number of currently active patches
Mang.Patches.unpatchOwner(owner)Removes every patch belonging to a specific mod owner
Mang.Patches.unpatchTarget(target)Removes all patches attached to a specific method
Mang.Patches.unpatchAll()Removes all active patches across the entire game
lua
Mang.Patches.unpatchOwner("my-mod")

When the last patch on a target method is removed, MLua automatically restores the game's original unpatched code.

Discovering Targets ​

Not sure what methods exist in the game assembly? Use Mang.Reflection to explore:

lua
give Mang.Reflection

local targets = Mang.Reflection.patchTargets()
for i = 1, targets.Count do
    print(targets:Get(i))
end
FunctionDescription
Mang.Reflection.types()Lists all registered type names
Mang.Reflection.hasType(name)Checks whether a type is registered
Mang.Reflection.members(name)Lists instance methods and fields for a type
Mang.Reflection.staticMembers(name)Lists static methods and fields for a type
Mang.Reflection.patchTargets()Lists all methods currently available for patching
Mang.Reflection.resolvePatch(target, argc)Resolves a target name and argument count to a canonical signature
