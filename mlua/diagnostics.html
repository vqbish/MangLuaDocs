Diagnostics ​

Every diagnostic carries a code, a source location, and a message. Codes are grouped by the compiler stage that produced them, so the prefix alone tells you roughly where in the pipeline the problem was caught.

Code Ranges ​

RangeStageMeaning
MLUA1xxxLexerMalformed tokens: unterminated strings, bad numbers, invalid escapes
MLUA3xxxParserGrammar errors: missing end, unexpected token, malformed declaration
MLUA42xxAccessVisibility violations on private and protected members
MLUA43xxDeclarationsBad override, final, abstract, or interface implementation
MLUA44xxTypesUnknown members, wrong argument types, invalid assignments and operators

Errors are always reported using the code from the earliest stage that fails. A chunk with a lexer error, for example, is never parsed or type-checked, since later stages depend on earlier ones succeeding.

Frequently Seen Codes ​

CodeMessageTypical cause
MLUA3001unexpected token after chunk bodyAn extra end, or a block closed twice
MLUA3013unexpected token in type bodyA plain statement placed inside a class or interface body
MLUA3017expected an expressionA declaration keyword used where a value was expected
MLUA4206member is private to a classA private member read from outside its declaring class
MLUA4207member is protected in a classA protected member read from outside the class hierarchy
MLUA4403operator applied to the wrong typeFor example, # used on a value that has no length
MLUA4404cannot assign one type to anotherThe annotation and the assigned value's type don't match
MLUA4410type has no member named ...A typo, the wrong type, or a member that was never declared
MLUA4411argument expects one type but received anotherA call argument doesn't satisfy the parameter's declared type
MLUA4412enum member is read onlyAn assignment targets an enum member instead of a variable

Reading a Diagnostic ​

Diagnostics follow a fixed format:

=test:24:52 MLUA4206: secret is private to Base
PartMeaning
=testThe chunk name - typically the file being compiled
24:52Line and column where the offending token starts
MLUA4206The diagnostic code
(remainder)A human-readable explanation of what was rejected and why

This format is stable and safe to parse with tooling - editors and build scripts can extract the chunk, position, and code with a simple pattern match.

Severity ​

There is only one severity level: error. A chunk with at least one diagnostic does not run - a mistyped member name, an illegal override, or a type mismatch is caught before the game ever executes that code, rather than surfacing as a runtime crash mid-session.

There are no warnings and no suppression directives (no // eslint-disable-style escape hatch). If you deliberately want a check relaxed for a specific value, annotate it as any or object instead - this makes the relaxation visible in the source rather than hidden in a comment.

Strict analysis versus runtime-checked execution ​

The strict mode used by AnalyzeSource reports all type and access errors. The runtime-checked mode used during execution keeps syntax and type-mismatch errors but allows dynamic fields.
