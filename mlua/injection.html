Class Injection ​

Want your MLua script to behave just like a native Unity MonoBehaviour? That is exactly what class injection does. While an ordinary class is just a script object, an injected component is an actual Unity component attached to a GameObject that receives standard Unity lifecycle events like Update, Start, and Awake.

Complete Example ​

Here is how you create a component that rotates a cube every frame:

lua
give UnityEngine

@[Component("Spinner")]
class Spinner : MonoBehaviour
    public speed = 90

    public function Update()
        self.transform.Rotate(0, self.speed * Time.deltaTime, 0)
    end
end

-- Create a cube and attach our custom MLua component to it
local cube = GameObject.CreatePrimitive(PrimitiveType.Cube)
local spinner: Spinner = cube:AddComponent<Spinner>()

-- Access its properties
spinner.speed = 45

-- Verify it is on the GameObject
assert(cube:GetComponent<Spinner>() == spinner)

In this example:

  • cube is the Unity GameObject.
  • spinner is your custom MLua component instance.
  • Inside any method, self refers to your component instance.
  • self.gameObject gives you the attached GameObject.
  • self.transform gives you its Transform.

The @[Component] Attribute ​

The @[Component("Spinner")] attribute gives your class a component alias. This registers your script class with the engine's component system so Unity knows how to instantiate and route messages to it.

Adding and Finding Components ​

You can attach components using generic syntax or by inferring the type from an annotated local variable:

lua
-- Explicit generic syntax
local spinner: Spinner = cube:AddComponent<Spinner>()

-- Or automatic inference from local variable type
local spinner: Spinner = cube:AddComponent()

-- Fetch an existing component from the object
local found: Spinner = cube:GetComponent<Spinner>()
assert(found == spinner)

GetComponent looks for an existing component on that GameObject - it will return nil if one hasn't been added yet.

Inheritance and Base Components ​

You can build hierarchies of components using inheritance and abstract classes:

lua
@[Component("BaseMotor")]
abstract class BaseMotor : MonoBehaviour
    public ticks = 0

    public function Update()
        self.ticks = self.ticks + 1
    end
end

@[Component("FastMotor")]
class FastMotor : BaseMotor
    public function Start()
        print("FastMotor started!")
    end
end

-- Attach the concrete derived component
local motor: FastMotor = cube:AddComponent<FastMotor>()

-- Fetch it by its base type
local base: BaseMotor = cube:GetComponent<BaseMotor>()
assert(base == motor)

Note that abstract classes cannot be added directly to a GameObject.

Unity Lifecycle Events ​

MLua components receive standard Unity lifecycle callbacks. While init is the constructor for the script instance, you should use Awake or Start for anything that needs the bound GameObject or Transform:

MethodWhen Unity calls it
Awake()Called immediately when the component is created and attached to the GameObject
OnEnable()Called whenever the GameObject or component becomes active/enabled
Start()Called once before the very first frame update
Update()Called every single frame - perfect for movement, input, and timers
FixedUpdate()Called on a fixed physics timestep - ideal for Rigidbody physics calculations
LateUpdate()Called every frame after all Update calls have finished - great for camera tracking
OnDisable()Called whenever the GameObject or component is deactivated
OnDestroy()Called right before the component or GameObject is destroyed

Troubleshooting ​

ProblemSolution
MonoBehaviour not foundMake sure you included give UnityEngine at the top of your script
Method doesn't run every frameDouble check the spelling of Update(), FixedUpdate(), or Start()
Cannot add abstract classYou cannot attach an abstract class directly - create and attach a concrete subclass instead
Component returns nil on GetComponentEnsure you called AddComponent on the object first, or check that you are querying the right GameObject
